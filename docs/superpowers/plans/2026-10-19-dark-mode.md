# Dark Mode for the Signed-in App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A header switch that flips every signed-in screen between light and Graphite dark, remembered per device, with landing and auth pages always light.

**Architecture:** The theme is a `dark` class on `<html>`, owned by a `ThemeScope` mounted only in the `_authed` layout: a body script applies the stored choice before first paint, a layout effect applies it on client navigation in, and its cleanup removes it on the way out (sign-out, any move to a public page). The choice is stored in `localStorage` as `light` | `dark`. Tokens get `.dark` values in `app.css`; the accent is split into an ink token (`--primary`, text/borders/rings) and a fill token (`--primary-fill`, solid backgrounds with white labels), and the literal-colour sweep moves hard-coded whites and hexes onto tokens.

**Tech Stack:** TanStack Start/Router 1.170 (`ScriptOnce`), Tailwind v4 (`@custom-variant`), shadcn/ui on Base UI (`Switch`), sonner, vitest (node env, `src/**/*.test.ts` only).

**Spec:** `docs/superpowers/specs/2026-10-19-dark-mode-design.md` (palette mock: https://claude.ai/artifact/Km8FCHLuGpL9Tmx31P6Mvp). Builder choices the spec left open are made here and marked **Decision**.

## Global Constraints

- Light is the default on first load; no following of the device's light/dark setting; stored values are exactly `light` or `dark`, no `system`.
- Graphite palette (spec values): page `#101216`, workspace `#121419`, card `#181b21`, sidebar `#14171c`, text `#e8eaee`, muted text `#9aa1ad`, border `#2a2f38`, accent `#7aa8ea`, soft accent surface `#1a2740`, button fill `#3069c0` with white label.
- Status tones, ink on tint: review `#93b9f0` on `#1a2740`, progress `#bdb0ee` on `#27213f`, warning `#eac26e` on `#33290f`, success `#85d3a6` on `#12291d`, danger `#f0a3a3` on `#361b1b`, neutral `#b1b7c2` on `#22262d`.
- Contrast floor in dark: body 4.5:1 minimum (mock: 14.3 body, 6.6 muted, 7.1 accent text, 5.4 button label, every pill ≥ 7.4).
- The switch is the repo's `~/components/ui/switch`, labelled "Dark mode" for assistive tech, 44px target on phones, visible focus ring, no motion under `prefers-reduced-motion`.
- Switch appears in exactly three headers: staff/admin/cashier/system-admin bar, applicant desktop top bar, applicant phone header. The service editor, apply wizard and onboarding are themed but get no switch.
- Landing, sign-in, register, forgot/reset password stay light and must not be blocked from going dark later. Printed/downloaded documents (PDFs, acknowledgments, verification forms) stay light. No email theming. No layout redesign.
- **Light must not shift.** Every replacement resolves to the identical colour in light (`bg-white` → `bg-card` is `#ffffff` in light). Components shared with landing/auth (`civic-identity`, `AuthSidePanel`, `SiteHeader`) must work in both because those pages never get `.dark`.
- `.dark` rules in `app.css` go after `:root` (same specificity, later wins). Anything under `@theme inline` is inlined into utilities and cannot be overridden by `.dark`; only `var(--x)` references can.
- Scoped wrappers (`.citizen-portal`, `.apply-wizard`) redefine `--muted-foreground`/`--body`/`--destructive` and beat an inherited `.dark` value; they need their own `.dark` variants. Dialogs that portal out re-apply `.apply-wizard`.
- **No commits.** The user reviews code first and commits themselves (project memory). Each task ends with a checkpoint, not a commit.
- Verification commands: `npx vitest run`, `npx tsc --noEmit`, `npx eslint <paths>`. User views the app in Safari: use the Playwright WebKit browser when installed and say so if it is not.

## Review Focus

- Device OS set to dark while the app is on light: nothing may turn dark (today's latent `dark:` utilities follow the OS; the new variant must follow only the class). Test: Playwright `prefers-color-scheme: dark` emulation, light theme, screens unchanged. (Task 1, Task 11)
- `localStorage` blocked or throwing (private window): app stays light, the switch still flips the theme for the session, nothing throws. (Task 1 unit test)
- First paint on a hard reload of a signed-in page in dark: no light frame. (Task 1 verification)
- Portaled UI opened in dark (dialogs, dropdown/select/popover, command palette, sheet, toasts, tooltips, calendar): none left light. (Tasks 5, 11)
- 320px phone header with brand, search, bell, switch and avatar: no horizontal scroll, switch still 44px tall. (Task 4)
